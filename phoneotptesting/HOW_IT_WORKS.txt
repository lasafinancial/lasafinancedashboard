SECTION 1: OVERVIEW
----------------------------------------------------------------

This app implements a real SMS OTP (One-Time Password) login flow
using Twilio Verify API. The user enters their Indian phone number,
receives a real 6-digit SMS on their phone, enters it, and gets
logged in if the code is correct.

The stack is:
  - Backend: Node.js + Express (server.js)
  - Frontend: Vanilla HTML + CSS + JavaScript (public/index.html)
  - SMS Service: Twilio Verify API (NOT Twilio SMS, we use Verify!)

SECTION 4: BACKEND — server.js
----------------------------------------------------------------

Dependencies used:
  - express   : Web server framework
  - twilio    : Official Twilio Node.js SDK
  - cors      : Allows frontend to call the backend API
  - dotenv    : (installed but not used here; creds are hardcoded)

How it works:

1. The Express server is initialized and serves the `public/`
   folder as static files (so visiting localhost:3000 shows the UI).

2. Two API routes are exposed:

   POST /send-otp
   ─────────────
   - Receives: { phone: "9876543210" } in request body
   - Auto-prepends +91 if phone doesn't start with +
   - Calls: client.verify.v2.services(serviceSid).verifications.create()
     with { to: "+919876543210", channel: "sms" }
   - Twilio sends a real 6-digit OTP SMS to the phone number
   - Returns: { success: true, message: "OTP sent to ..." }

   POST /verify-otp
   ────────────────
   - Receives: { phone: "9876543210", code: "123456" } in request body
   - Auto-prepends +91 if needed
   - Calls: client.verify.v2.services(serviceSid).verificationChecks.create()
     with { to: "+919876543210", code: "123456" }
   - Twilio validates whether the code is correct and not expired
   - If verificationCheck.status === "approved" → login success
   - If not → returns error message

3. Server listens on port 3000.

To start the server:
  node server.js

Or with npm:
  npm start

SECTION 5: FRONTEND — public/index.html
----------------------------------------------------------------

This is a single HTML file with embedded CSS and JavaScript.
It has 3 "screens" (divs), only one shown at a time:

  Screen 1 (screen-phone):
    - Input field for 10-digit Indian phone number
    - "+91" prefix is shown visually, added automatically in JS
    - "Send OTP" button calls POST /send-otp

  Screen 2 (screen-otp):
    - 6 individual input boxes (one per digit) for OTP entry
    - Auto-advances focus to next box as user types
    - Supports paste (e.g. user pastes "123456" from clipboard)
    - Backspace goes to previous box
    - "Verify OTP" button calls POST /verify-otp
    - "Resend OTP" button re-calls POST /send-otp
    - "Change number" goes back to Screen 1

  Screen 3 (screen-success):
    - Shows "Login Successful!" with animated checkmark
    - "Sign in again" resets everything back to Screen 1

Key JavaScript functions:
  sendOTP()   — Validates phone input, calls /send-otp, switches to OTP screen
  verifyOTP() — Collects 6 OTP digits, calls /verify-otp, shows success or error
  resendOTP() — Re-sends OTP using the same phone number
  goBack()    — Returns to phone input screen
  resetAll()  — Resets entire form to initial state

Design:
  - Dark glassmorphism UI (blurred glass card on gradient background)
  - Google Font: Inter
  - Animated gradient blobs in background
  - Smooth screen transitions with CSS animations
  - Loading spinner on buttons during API calls
  - Error messages auto-hide after 5 seconds

SECTION 6: HOW TO INTEGRATE INTO ANOTHER PROJECT
----------------------------------------------------------------

Step 1: Install dependencies in your project
  npm install express twilio cors

Step 2: Copy the backend API logic
  Copy the /send-otp and /verify-otp route handlers from server.js
  into your existing Express server (or Next.js API routes, etc.)
  
  The core Twilio calls are:
  
  // Initialize client once
  const client = twilio(accountSid, authToken);
  
  // Send OTP
  await client.verify.v2
    .services("[YOUR_SERVICE_SID]")
    .verifications.create({ to: "+91XXXXXXXXXX", channel: "sms" });
  
  // Verify OTP
  const check = await client.verify.v2
    .services("[YOUR_SERVICE_SID]")
    .verificationChecks.create({ to: "+91XXXXXXXXXX", code: "123456" });
  
  if (check.status === "approved") {
    // user is authenticated!
  }

Step 3: Integrate the frontend
  - Copy the 3 screen divs and the JavaScript from index.html
  - Adjust the fetch() calls if your API routes have different paths
  - The CSS can be adapted to match your project's design system

Step 4: Store credentials securely
  - Move the Twilio credentials to a .env file (never hardcode in production)
  - Use process.env.TWILIO_ACCOUNT_SID, etc.
  
  .env file example:
    TWILIO_ACCOUNT_SID=[YOUR_ACCOUNT_SID]
    TWILIO_AUTH_TOKEN=[YOUR_AUTH_TOKEN]
    TWILIO_SERVICE_SID=[YOUR_SERVICE_SID]

  In server.js:
    require('dotenv').config();
    const accountSid = process.env.TWILIO_ACCOUNT_SID;
    const authToken  = process.env.TWILIO_AUTH_TOKEN;
    const serviceSid = process.env.TWILIO_SERVICE_SID;

Step 5: Phone number format
  - Always send phone numbers to Twilio in E.164 format: +91XXXXXXXXXX
  - The current code auto-prepends +91 if not present
  - For international support, let the user select a country code

SECTION 7: TWILIO VERIFY API — KEY FACTS
----------------------------------------------------------------

- Twilio VERIFY is different from Twilio SMS.
  Verify is specifically built for OTP authentication.
- OTP codes expire after 10 minutes.
- Each verification attempt is tracked by Twilio.
- After 5 failed attempts, the verification is locked.
- On paid plans, you can send to ANY phone number worldwide.
- On trial plan, only verified numbers receive OTPs.
- Pricing: ~$0.05 per successful verification (on paid plan).
- Twilio Verify docs: https://www.twilio.com/docs/verify/api
